# Data Model

SQLite via Node's built-in `node:sqlite` module (`server/db.js` / `server/schema.js`). No ORM —
plain prepared statements, so the SQL is always visible and auditable.

## `transactions`

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `date` | TEXT | `YYYY-MM-DD` |
| `type` | TEXT | `INCOME` \| `EXPENSE` \| `TRANSFER` |
| `amount_minor` | INTEGER | integer minor units, must be `> 0` |
| `currency` | TEXT | default `PKR` |
| `category_id` | INTEGER | FK → `categories`, nullable |
| `account_id` | INTEGER | FK → `accounts`, nullable |
| `payment_method` | TEXT | nullable |
| `is_fixed` | INTEGER | 0/1 |
| `is_essential` | INTEGER | 0/1 |
| `recurring_template_id` | INTEGER | set when generated by a recurring template |
| `transfer_pair_id` | INTEGER | reserved for double-entry transfer linking |
| `description`, `notes` | TEXT | nullable |
| `created_at`, `updated_at` | TEXT | |

## `categories`

`id`, `name`, `kind` (`fixed`\|`variable`), `essential` (0/1), `icon`, `color`, `archived` (0/1).
Archiving keeps a category on past transactions but hides it from new-transaction pickers.

## `accounts`

`id`, `name`, `type`, `archived`. Used to tag which account a transaction belongs to; the app
does not currently track running account balances — see [decisions.md](decisions.md).

## `budgets`

`id`, `category_id` (FK), `month` (`YYYY-MM`), `amount_minor`. Unique on `(category_id, month)` —
setting a budget for a category twice in the same month updates the existing row.

## `recurring_templates`

`id`, `description`, `type` (`INCOME`\|`EXPENSE`), `amount_minor`, `category_id`, `account_id`,
`is_fixed`, `is_essential`, `frequency` (`weekly`\|`biweekly`\|`monthly`\|`yearly`), `start_date`,
`end_date` (nullable), `status` (`active`\|`paused`), `last_generated_date`.

## `emergency_fund`

Single-row settings table (`id` constrained to `1`): `target_months`, `current_reserve_minor`.
The reserve is a manually-entered figure, not derived from account balances (see
[decisions.md](decisions.md)).

## `debts`

`id`, `name`, `original_balance_minor`, `current_balance_minor`, `interest_rate`,
`min_payment_minor`, `extra_payment_minor`, `due_day`.

## Design notes

- **Every monetary column is `_minor`** — integer minor units, never a float.
- **Foreign keys are enforced** (`PRAGMA foreign_keys = ON`).
- **No ORM migrations system** — the schema is idempotent `CREATE TABLE IF NOT EXISTS` statements
  in `schema.js`, safe to run on every startup. For a single-user local app this is simpler and
  more transparent than a migration framework; see [decisions.md](decisions.md) for the tradeoff.
- **Tests run against a real schema**, not a mock — `server/test/helpers/testDb.js` creates an
  in-memory SQLite database via the same `initializeSchema()` function production uses.
