# Calculations Reference

Every formula below is implemented in `server/services/` as a pure function (no side effects,
takes data in and returns a result), and covered by tests in `server/test/`. This document exists
so you can verify the app's math independently instead of trusting a black box.

## Monetary representation

All amounts are stored as **integer minor units** (paisa/cents — `amount_minor`), never floating
point. `Rs 1,234.56` is stored as `123456`. This avoids the classic `0.1 + 0.2 !== 0.3` class of
bug entirely for anything that stays in minor units. Conversion to/from major units (for display
or user input) happens only at the UI boundary, via `Math.round(value * 100)` and `value / 100`.

## Summary (`services/summary.js`)

```
netIncomeMinor      = Σ amount_minor where type = INCOME
fixedExpensesMinor  = Σ amount_minor where type = EXPENSE and is_fixed = true
variableExpensesMinor = Σ amount_minor where type = EXPENSE and is_fixed = false
totalExpensesMinor  = fixedExpensesMinor + variableExpensesMinor
netMarginMinor      = netIncomeMinor − totalExpensesMinor
marginRate          = netIncomeMinor > 0 ? (netMarginMinor / netIncomeMinor) × 100 : null
```

`TRANSFER` transactions are excluded from every sum above by the `WHERE type != 'TRANSFER'`
clause — not filtered out after the fact, excluded at the query.

## Monthly totals (`services/monthly.js`)

Same formulas as Summary, scoped to one calendar month via `strftime('%Y-%m', date) = ?`. Month
boundaries are inclusive of both the first and last day.

`computeAverageMonthlyFixed` averages fixed spend only across months that actually have
transaction activity — an empty prior month doesn't drag the average toward zero.

## Margin Health (`services/marginHealth.js`)

```
fixedRatio = fixedExpensesMinor / netIncomeMinor   (only when netIncomeMinor > 0)

INSUFFICIENT_DATA  if transactionCount = 0 or netIncomeMinor ≤ 0
NEGATIVE           if netMarginMinor < 0
TIGHT              if marginRate < 10  or  fixedRatio > 0.7
STABLE             if marginRate < 20
HEALTHY            otherwise
```

## Month-over-month (`services/momComparison.js`)

```
pctChange(current, previous) =
  previous = 0 and current = 0  → 0
  previous = 0 and current ≠ 0  → null   (undefined percent change, not Infinity)
  otherwise                     → (current − previous) / previous × 100
```

## Spending-leak detection (`services/leakDetector.js`)

A category is flagged when **all** of:
- it had nonzero spend in the previous month (a 0 → anything jump has no percent baseline)
- this month's spend is at least Rs 50 (`MIN_ABSOLUTE_MINOR = 5000`) — a noise floor so a
  category jumping from Rs 2 to Rs 4 doesn't get reported
- the month-over-month increase is ≥ 15% (`INCREASE_THRESHOLD_PCT`)

## Budget variance (`services/budgetVariance.js`)

```
varianceMinor    = budgetMinor − actualMinor
remainingMinor   = max(0, varianceMinor)         (never negative)
utilizationPct   = budgetMinor > 0 ? actualMinor / budgetMinor × 100 : 0
```

## Emergency fund (`services/emergencyFund.js`)

```
targetMinor      = round(fixedBaselineMinor × targetMonths)
remainingMinor   = max(0, targetMinor − currentReserveMinor)
progressPct      = targetMinor > 0 ? min(100, currentReserveMinor / targetMinor × 100) : 0
monthsCovered    = fixedBaselineMinor > 0 ? currentReserveMinor / fixedBaselineMinor : null
```

`fixedBaselineMinor` here is the *average* monthly fixed spend (see above), not a cumulative
all-time total — otherwise the target would grow indefinitely as history accumulates.

## Debt payoff (`services/debtPayoff.js`)

Standard fixed-payment loan amortization, not a simplified approximation:

```
monthlyRate = interestRate / 100 / 12
interestPortion = currentBalanceMinor × monthlyRate

if currentBalanceMinor ≤ 0:            0 months (already paid off)
if monthlyPaymentMinor ≤ 0:            null (no payment, never pays off)
if monthlyRate = 0:                    ceil(currentBalanceMinor / monthlyPaymentMinor)
if monthlyPaymentMinor ≤ interestPortion: null (payment doesn't even cover interest — never)
otherwise:
  months = −ln(1 − interestPortion / monthlyPaymentMinor) / ln(1 + monthlyRate)
  return ceil(months)
```

This is presented in the UI as an estimate, explicitly labeled as assuming a constant payment
and rate — never as a guarantee.

## Recurring transaction generation (`services/recurringEngine.js`)

Occurrences are generated by repeatedly applying `addInterval` from a template's
`last_generated_date` (or `start_date` if never generated) up to "today," inclusive. For
`monthly`/`yearly` frequencies, the **anchor day** (the day-of-month from the template's original
`start_date`) is preserved across the whole sequence — a template starting on the 31st clamps to
the 28th in February but returns to the 31st in March, rather than permanently drifting to
whatever the last clamped day happened to be. See `server/test/recurringEngine.test.js` for the
exact behavior this guarantees.

## Cash-flow forecast (`services/cashFlowForecast.js`)

```
forecastIncomeMinor  = Σ (recurring INCOME template amount × occurrences next month)
forecastFixedMinor   = Σ (recurring fixed EXPENSE template amount × occurrences next month)
forecastVariableMinor = average variable spend over the last 3 active months
forecastMarginMinor  = forecastIncomeMinor − forecastFixedMinor − forecastVariableMinor
```

Always labeled FORECAST in the UI, never presented as a guaranteed balance. If neither recurring
templates nor spending history exist, no forecast is shown at all — nothing is fabricated to fill
the gap.
